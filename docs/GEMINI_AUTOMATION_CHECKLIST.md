## 0. 준비 — `git pull` 할 때마다 (Windows)

앱·Native Host·확장 프로그램(서비스 워커)·Gemini 탭은 **각각 따로** 새 코드로 바뀝니다. 또 Chrome은 확장이
`connectNative`를 부를 때마다 Host 프로세스를 하나씩 띄우므로, **Chrome 프로필이 여럿이거나 확장 사본이 여럿이면 Host도 여럿**
앱에 붙습니다. 앱은 연결 확인 때 이 모든 것을 확인하고, 하나라도 맞지 않으면 **보내지 않고** 진단 정보를 보여 줍니다.

1. **저장소 갱신** — 저장소 폴더에서 PowerShell:
   ```powershell
   git pull
   npm install
   npm run build
   ```
   이어서 같은 폴더의 **`SETUP_GEMINI.bat`**을 실행합니다. Node.js 확인과 Native Host 등록(고정 확장 ID 포함)을 자동으로 합니다. 여러 번 실행해도 안전합니다.
2. **앱 완전히 종료 후 다시 실행** — 평소 실행 방식 그대로 (`npm run dev` 또는 `npm run preview` 또는 `START_WINDOWS.bat`).
   설치한 exe를 쓰고 있다면 `npm run dist:win` 으로 만든 새 설치본을 다시 설치해야 합니다(이전 exe는 이전 코드). 설치용 EXE에는 Native Host가 아직 들어 있지 않으므로 Host 등록은 저장소 폴더의 `SETUP_GEMINI.bat`으로 합니다.
3. **Chrome 확장 새로고침 또는 다시 로드** — `chrome://extensions` (오른쪽 위 개발자 모드 켜기)
   - **이번 갱신부터 확장 ID가 고정값 `ekibpgmnknamcpplppceoaogmcbcabbo` 로 바뀝니다.** 예전에 불러온 카드의 ID가 이와 다르면 그 카드를 **제거**한 뒤 「압축해제된 확장 프로그램을 로드합니다」로 저장소의 `extension` 폴더를 다시 불러오세요.
   - GOMO Gemini Connector 카드의 **↻ 새로고침** → 버전이 **0.2.8**인지, ID가 **`ekibpgmnknamcpplppceoaogmcbcabbo`** 인지 확인.
   - **「서비스 워커」 링크**(뷰 검사)를 눌러 열린 콘솔 첫 줄에
     `GOMO background protocol 2 build 0.2.8 file gomo-sw.js manifest 0.2.8` 이 보여야 합니다.
     안 보이거나 다른 내용이면(0.2.2까지는 서비스 워커 파일이 `background.js`였음): 확장을 **삭제** → 「압축해제된 확장 프로그램을 로드합니다」로
     `<저장소>\extension` 을 다시 로드 → 콘솔 다시 확인.
   - 「세부정보」의 소스 경로가 git pull 한 저장소의 `extension` 폴더인지 확인.
   - 다르면 다른 폴더를 불러온 것입니다 → 제거 후 「압축해제된 확장 프로그램을 로드합니다」로 `<저장소>\extension` 을 다시 불러옵니다.
4. **다른 Chrome 프로필 확인** — Chrome 오른쪽 위 프로필 아이콘에 프로필이 여러 개면, **각 프로필에서** `chrome://extensions` 를 열어
   GOMO Gemini Connector가 있는지 봅니다. 있으면 그 프로필에서도 ↻ 새로고침(0.2.8)하거나, 쓰지 않으면 **제거**합니다.
5. **Chrome 완전히 종료 후 다시 켜기**
   - 모든 Chrome 창을 닫고, 작업 표시줄 오른쪽 트레이(^)에 Chrome 아이콘이 있으면 우클릭 → 종료.
   - (선택) 남은 Host 프로세스 확인 — PowerShell:
     ```powershell
     Get-CimInstance Win32_Process -Filter "name='node.exe'" | Where-Object CommandLine -like '*host.mjs*' | Select-Object ProcessId, CommandLine
     ```
     Chrome을 끈 상태에서 여기에 나오는 것은 남은 Host입니다 → `Stop-Process -Id <ProcessId>` 로 종료.
     (앱을 `npm run dev` 로 띄운 node.exe는 `host.mjs` 가 아니므로 여기에 나오지 않습니다.)
   - Native Host 재등록은 보통 필요 없습니다(등록된 `gomo-host.cmd` 가 저장소의 `native-host\host.mjs` 를 직접 실행).
     저장소 폴더를 옮겼거나 이번처럼 확장 ID가 바뀌었거나 연결 확인에서 `HOST_OUTDATED` 가 계속 나올 때만
     저장소 폴더의 `SETUP_GEMINI.bat`을 다시 실행하세요. 수동이면:
     ```powershell
     # 반드시 저장소 폴더에서 실행. ID를 생략하면 고정 ID를 씁니다.
     npm run native:register
     npm run native:check
     ```
6. **Gemini 탭 열기/새로고침** — `gemini.google.com` 을 열거나 F5. 로그인 상태 확인, 입력창은 비워 둡니다.
7. **연결 상태 확인** — 앱 → 환경 설정 → AI 연결 → **연결 상태 확인**. 「연결·진단 결과」가 대략 이렇게 나와야 합니다:

## 1. 선택자 진단 (아무것도 보내지 않음)

환경 설정 → AI 연결 → **선택자 진단 (전송 없음)** 클릭 → 결과 JSON의 **복사** 버튼으로 복사해 개발자에게 전달.

출력 형식(예):

```json
{
  "ok": true,
  "tab": { "id": 123, "title": "Gemini" },
  "report": {
    "kind": "gomo.selector-probe.v1",
    "selectorsVersion": "2026-11-24",
    "url": "https://gemini.google.com/app",
    "summary": {
      "composer": "rich-textarea [contenteditable=\"true\"][role=\"textbox\"]",
      "composerEmpty": true,
      "sendButton": "button[aria-label*=\"보내기\"]",
      "sendEnabled": false,
      "stopButton": null,
      "userQueries": 0,
      "modelResponses": 0,
      "signIn": false,
      "blocked": false
    },
    "groups": { "composer": [ { "selector": "...", "count": 1, "visible": 1, "verified": false } ], "...": [] }
  }
}
```

판정
- [ ] `summary.composer`가 null이 아님 (입력창 인식)
- [ ] `summary.sendButton`이 null이 아님 — 입력창이 비어 있으면 Gemini가 전송 버튼을 숨기거나 비활성화할 수 있으니, null이면 입력창에 글자 하나를 직접 쓴 상태로 한 번 더 진단(진단은 입력·전송하지 않음)
- [ ] 이전 대화가 있는 탭이면 `userQueries`/`modelResponses`가 대화 수와 맞음
- [ ] `signIn`=false, `blocked`=false
- [ ] Gemini 화면에 아무것도 입력·전송되지 않았음

## 3-A. 이후 단계 자동화 (단계별 1회씩, 같은 작품으로 이어서)

공통: `git pull` → `npm run build` → 앱 재시작. 확장은 0.2.8로 ↻ 새로고침(3-C·3-D), Host 재등록은 필요 없음.
모든 단계가 같은 Gemini 탭·지금 열린 대화를 이어 씁니다. 각 요청에는 새 요청 표식이 붙어 이번 답변만 수집합니다.

**장면 구성 (스토리보드)**
- [ ] 화풍·연출안 선택 → 「스토리보드로」 → 「AI 장면 구성 시작」 한 번 클릭 → Gemini에 질문이 한 번만 올라감
- [ ] 모달 진행 단계: 연결 확인 → 프롬프트 전송 → 응답 대기 → 응답 수집 → JSON 검증 → `장면 구성 완료`
- [ ] 긴 장면표(장면 20개 이상)도 끝까지 수집됨: 모달 「Gemini 응답 원문 보기」 마지막이 JSON 닫는 괄호로 끝나는지, 장면 수가 Gemini 화면과 같은지
- [ ] 결과 패널의 장면 목록 → 「장면표 확인하기」로 패널을 닫고 장면표를 확인. 다음 단계는 화면 하단 「다음: 생성 프롬프트」로 이동
- [ ] 낭독 문장을 Gemini가 바꾸면 `오류 · JSON 검사 실패`(원문 불일치 안내)로 적용 안 됨
- [ ] 진행 중 모달을 닫으면 스토리보드 화면 상단에 `Gemini 스토리보드 · (단계)` 배너, 끝나면 자동 반영 + 알림

**생성 프롬프트**
